## Features added

| Feature | File | What it does |
|---|---|---|
| Single-writer event loop | `keel/kernel/loop.py`, `guard.py` | `Kernel.handle()` is the only mutator; `WriteGuard` raises on outside, cross-thread or re-entrant writes. `AsyncKernelRunner` runs it live over the adapter's queues. |
| Versioned slot store | `keel/kernel/slots.py` | Value, version, source, confidence, time, lock, history. Version bumps only on real change. Corrections lock against later perception. |
| Call ledger | `keel/kernel/ledger.py` | Checked status machine; sha256 idempotency key over (session, tool, canonical args); exactly-once blocking; "maybe executed" state for cancelled writes. |
| Goals and bindings | `keel/kernel/plan.py` | Steps bind args to slots / constants / earlier results; the schema the LLM will emit in phase 4. |
| Invalidation + converge | `keel/kernel/loop.py` | Cancels exactly the calls whose inputs changed, with the reason and the slot versions. |
| Commit fence | `keel/kernel/fence.py` | Writes wait for end-of-turn + a quiet period after the last change they read. |
| Reconciliation | `keel/kernel/reconcile.py` | Probe / idempotent retry / "can't confirm", never a blind re-send. |
| Fast-path phrases | `keel/paths/fast.py`, `[phrases]` in config | Templates filled only from confirmed state; hold, correction, progress, status. |
| Manifest compiler (step 1) | `keel/compiler/manifest.py` | Explicit hints: MCP annotations, τ²-style labels, HTTP method. Else `unknown` → treated as write. |
| Simulator | `keel/sim/` | Virtual-clock harness, mock tools with latency/faults/cancel semantics, a World that records real effects, a scripted interpreter. |
| Invariant checker | `keel/sim/invariants.py` | I1–I5 from any trace; run by every kernel test. |

## Decisions and why

1. **Converge, not event handlers per case.** After every event the kernel
   recomputes what the goal needs and diffs it against the ledger. Stale-call
   cancellation, duplicate prevention and read reuse all fall out of one
   comparison of idempotency keys, instead of special cases per event type.
2. **Arguments are bound to slots, not copied.** This is what lets Keel say
   exactly which calls a correction invalidates ("cancel exactly the calls
   that read the old version") and leave the rest alone.
3. **An interrupt alone cancels nothing.** Only a change to something a call
   read does. This is the difference from Pipecat's default
   `cancel_on_interruption=True`.
4. **Writes to one tool are serialised.** Found by the invariant checker: in
   one tick the corrected write was dispatched before the old one was
   cancelled, which produced a duplicate. Now a write waits while another
   write to that tool is in flight or in doubt. Cost: two genuinely separate
   writes to one tool run one after another.
5. **A cancelled in-flight write is "maybe executed".** We asked the world to
   stop; we can't know it did. It blocks further writes to that tool until
   a result, our timeout, or a probe settles it (K19).
6. **Committed writes are never re-sent on a correction.** Keel says "that
   was already submitted… it needs a change" and waits for a new plan.
7. **Unresolvable doubt ends the goal truthfully** ("I can't confirm whether
   that went through") instead of stalling or guessing.
8. **Idempotent retry is off by default.** Even for tools marked idempotent, a
   re-send appears as a duplicate state-changing call in any trace-based
   count, and the guide scores "zero duplicate state-changing calls". Probing
   is preferred.
9. **Correction acknowledgment is spoken after cancellation** in the same
   tick, so the cancel is never delayed behind speech.
10. **"What X should I use?" is asked only after the slow path has answered**,
    so Keel never asks for something the LLM is about to supply.

## Default values and their sources (all in `config/keel.toml`)

| Setting | Value | Source |
|---|---|---|
| `floor.ack_after_ms` | 300 | Guide §1 "few hundred ms"; under the 600 ms drop-off found by Roberts & Francis (2013) |
| `fence.quiet_ms` | 600 | Roberts & Francis (2013) drop-off; **provisional**, phase 4 replaces it with our own measurement |
| `fence.stale_turn_ms`, `floor.progress_after_ms` | 1000 | Jefferson (1988): ~1 s "standard maximum" silence |
| `calls.timeout_ms` | 10000 | **provisional** (K18): kit latency unknown |
| `perception.clarify_below` | 0.6 | **provisional**: calibrated in phase 4 |

## How to use it

```python
from keel.config import load_config
from keel.sim.harness import Simulation
from keel.sim.mock_env import ToolBehaviour
sim = Simulation(config=load_config(), behaviours={"book": ToolBehaviour(effect=True)}, script={...})
res = sim.run([manifest_event, text_event, ...])      # res.actions, res.records, res.env.world
```

## Known gaps (planned)

- **Commit conflicts wait for a replan.** In 356 of the 3072 grid runs the
  first booking landed before the correction, so there is no final response:
  Keel correctly refuses to book again and waits for a new plan. The slow
  path (phase 4) must receive this conflict and plan a modification.
- Argument validation against the tool's JSON Schema comes with the compiler
  (phase 3).
- The fence default is literature-based until phase 4 measures self-repairs.
